# Android app (Capacitor)

The Android app is the same game in a native WebView. The web files come from one of TWO Android builds (both write the git-ignored folder `dist-android`, so build one, sync it, then build the other). Both are the normal build with the CrazyGames SDK script removed, so CrazyGames code can never run inside the app. They differ only in the ad network:

| Build | Command | Ads | Use for |
| --- | --- | --- | --- |
| Store build (`android-play`) | `npm run build:android-play` | Google AdMob (test ids) | Google Play and other store builds |
| Direct build (`android-direct`) | `npm run build:android-direct` | Unity LevelPlay (ids from a local env file) | Independent / direct distribution |

Both keep the same package name, `com.spookydinerrush.game`. Samsung Galaxy Store publishing stays ON HOLD. The intro video stays in both.

## What is in the repo
- `capacitor.config.ts`: app name, `appId` (PROVISIONAL, `com.spookydinerrush.game`; it cannot change after the first store upload), web folder `dist-android`.
- `android/`: the generated Android Studio project. Edited by hand: `AndroidManifest.xml` (`sensorLandscape`), `MainActivity.java` (full screen, notch, no overscroll). The copied web files inside `android/app/src/main/assets/` are generated by `cap sync` and git-ignored.
- `src/platform/android.ts` and `androidLogic.ts`: app pause and resume, and the Back button. Only the Android build contains them (and the Capacitor files).
- `src/ads/`: the ads door the game uses (`index.ts`), the store-build-only AdMob file (`admobAds.ts`) with Google's TEST ids (`adIds.ts`), the direct-build-only LevelPlay files (`levelplayAds.ts`, `levelplayConfig.ts`, `levelplayDebug.ts`, `dailyCap.ts`), the shared 180 s timing (`timing.ts`). `src/game/reopenWithAd.ts` is the one place that grants the rewarded Reopen, for both restaurants and both networks.

## Build a debug APK (you, on your computer)
One-time setup: install Android Studio (it brings the Android SDK and a JDK). Node 22 or newer.
1. `npm ci`
2. `npm run android:sync:play` for the store build, or `npm run android:sync:direct` for the direct build (each builds `dist-android` and copies it into the Android project)
3. Easiest: `npm run android:open`, wait for Gradle to finish, then in Android Studio use Build > Build Bundle(s) / APK(s) > Build APK(s). Or from the terminal: `cd android` then `./gradlew assembleDebug` (Windows: `gradlew.bat assembleDebug`).
4. The file is `android/app/build/outputs/apk/debug/app-debug.apk`. To install: copy it to the phone and open it (allow "install unknown apps"), or with USB debugging on: `adb install -r app/build/outputs/apk/debug/app-debug.apk` (run from the `android` folder, path `app/build/outputs/apk/debug/app-debug.apk`).
After changing game code, run the same sync command again before rebuilding. To switch between the two builds, run the other sync command, then rebuild.
A debug APK is for testing only. The signed release build and the store checklist come in the release-prep step. Never commit a keystore or `local.properties`.

## Ads: store build (AdMob)
The game asks `ads` (`src/ads/index.ts`) for ads and never knows which network is behind it. Browser and CrazyGames builds use the CrazyGames SDK wrapper as before; the store build uses Google AdMob through `src/ads/admobAds.ts`. The networks are never mixed: the Android builds remove the CrazyGames script, and every build contains only its own network (each one is loaded by a dynamic import that Vite removes outside its own mode, `--mode android-play` for AdMob; `tests/adsafety.test.ts` and a bundle check cover it). The AdMob test app id stays in `AndroidManifest.xml` for both Android builds, because the AdMob SDK may refuse to start without it.
- Placements are exactly the existing ones: the mid-game ad at the calm moment after a level-up card (from Lv 3), and the rewarded "Watch an ad: reopen at full reputation" button on the Closed screen. No new placements.
- Numbers are unchanged: normal Reopen 55 reputation, rewarded Reopen 100, no bonus coins, 180 s between mid-game ads (one constant, `src/ads/timing.ts`, used by both networks).
- The reward is granted only after AdMob's own "reward earned" event (`onRewardedVideoAdReward`). Closing the ad early, a load or show failure, no fill or a 90 s timeout give no reward and the Closed screen says "No ad available right now. You can still reopen."
- Until AdMob has started (a second or two after launch), or if it fails to start, the app shows no ads and no rewarded button. It never falls back to CrazyGames.
- TEST ids only: Google's official test app id (in `AndroidManifest.xml`) and test interstitial and rewarded unit ids (`src/ads/adIds.ts`), and `isTesting: true`. REAL ids are NOT added; the owner supplies them in a later step (change the manifest meta-data `com.google.android.gms.ads.APPLICATION_ID` and `adIds.ts` together; a test checks that they match and that only Google test ids are present).
- Not done yet (needed before a public release): the consent form for EEA/UK players (Google's UMP), the privacy policy and the Play "Data safety" answers about advertising.

### Test the ads on your phone or emulator (test ads only)
One-time: Android Studio installed (brings the Android SDK and a JDK), Node 22 or newer, a phone with USB debugging on (or an emulator with Google Play services).
1. In the project folder: `git checkout feature/android-capacitor`, then `npm ci`.
2. `npm run typecheck` and `npm test` (all must pass), then `npm run android:sync:play` (builds `dist-android` and copies it, plus the AdMob plugin, into `android/`).
3. `cd android`, then `./gradlew assembleDebug` (Windows: `gradlew.bat assembleDebug`). The file is `android/app/build/outputs/apk/debug/app-debug.apk`. If Gradle stops with an SDK error, open the `android` folder in Android Studio once and let it finish syncing.
4. Install: `adb install -r app/build/outputs/apk/debug/app-debug.apk` (from the `android` folder), or copy the APK to the phone and open it.
5. Check, in this order, and write down what you see:
   - The app starts and reaches the title screen (a crash right at start usually means the manifest app id is wrong).
   - Play to Lv 3. After the level-up card, within a short calm moment a Google "Test Ad" full-screen ad appears; the kitchen and sound are frozen; closing it resumes the game exactly as before.
   - A second mid-game ad does NOT appear for the next 180 s.
   - Let reputation drop to 0: the Closed screen shows "Reopen" and, a few seconds after launch or later, "Watch an ad: reopen at full reputation". Plain Reopen: reputation 55.
   - Watch the rewarded test video to the end and close it: the restaurant reopens at 100 reputation. Close the video BEFORE the end: no reward, the text "No ad available right now. You can still reopen." shows.
   - Airplane mode: no ad, no crash, Reopen still works.
   - Back button while an ad is on screen does nothing; Home and back during an ad does not lose the game.
   - Optional: `adb logcat | grep -iE "Ads|AdMob|Capacitor"` shows the Mobile Ads SDK and any ad error. (`chrome://inspect` does not work with this build: `webContentsDebuggingEnabled` is false in `capacitor.config.ts`. The app has no CrazyGames script in `dist-android/index.html`, which `tests/adsafety.test.ts` and the bundle check cover.)

## Ads: direct build (LevelPlay)
The game asks `ads` (`src/ads/index.ts`) for ads and never knows which network is behind it. Browser and CrazyGames builds use the CrazyGames SDK wrapper as before; the direct build uses Unity LevelPlay (SDK 9.4.0, inside the community plugin `capacitor-levelplay-ads`, pinned to exactly 0.1.42) through `src/ads/levelplayAds.ts`. The two are never mixed: the Android builds remove the CrazyGames script, and the browser, CrazyGames and store builds contain no LevelPlay code or ids (the plugin is loaded by a dynamic import that Vite removes outside `--mode android-direct`; `tests/adsafety.test.ts` checks it).
- Placements: the mid-game ad at the calm moment after a level-up card (from Lv 3) and after a Reopen tap (both existed before), the rewarded "Watch an ad: reopen at full reputation" button on the Closed screen (existed before), and ONE new placement: a banner at the bottom of the title screen only (direct build only; the store build has no banner). The banner came with the earlier LevelPlay work and still needs the owner's explicit approval before a public release.
- Numbers are unchanged: normal Reopen 55 reputation, rewarded Reopen 100, no bonus coins, no lives, 180 s between mid-game ads (one constant, `src/ads/timing.ts`). New on top: at most 3 mid-game ads per calendar day (`src/ads/dailyCap.ts`, kept in the app storage). The LevelPlay dashboard also caps 3 per day and 1 per 5 minutes; both limits apply.
- The dashboard reward "Extra Life, amount 1" is only a label. The game has no lives; the reward is the existing rewarded Reopen (100 reputation), granted only after LevelPlay's reward event. LevelPlay can send that event after the ad closed, so a closed ad waits 2.5 s for it. Closing early, a load or show failure, no fill or a 90 s timeout give no reward and the Closed screen says "No ad available right now. You can still reopen."
- Ads are loaded ahead of time. The rewarded button only appears when a rewarded ad is loaded; a mid-game ad only runs when one is loaded, otherwise the game just goes on (nothing is queued). A failed load is tried again after 30 s.
- Banner: adaptive size, bottom of the screen, `isOverlap: false` (the game view is made shorter by the banner height, so it cannot cover the title). It is shown when the title screen opens and hidden when the title screen closes. There is only ever one banner.
- Until LevelPlay has started (a second or two after launch), if it fails to start (it retries 4 times, 30 s apart), or if the ids are missing, the app shows no ads and no rewarded button. It never falls back to CrazyGames.
- Privacy: nothing is set in code. No age setting is sent (the dashboard declaration "not directed to children" stands) and there is NO consent form yet for players in the EEA, UK and similar regions. A consent solution has to be chosen before a public release (see "Not done yet").
- Permissions: the manifest adds `com.google.android.gms.permission.AD_ID` (needed by LevelPlay on Android 13 and newer) next to INTERNET. The ad SDK adds more by itself (network state, and others); check the merged manifest of the APK before filling in the store privacy forms.

### Where the ids live (never in git)
1. Copy `.env.example` to `.env.android-direct.local` (same folder, next to `package.json`). Git ignores it.
2. Fill in the App Key and the three ad unit ids from the LevelPlay dashboard (Rewarded `Extra_Life`, Interstitial `Between_Levels`, Banner `Main_Menu_Banner`). Keep `VITE_LEVELPLAY_TEST=true` for test builds; remove the line or set it to `false` for a store build.
3. Ids go into the web bundle of the APK, so they are not secret from someone who unpacks the APK; keeping them out of git just keeps the public repository clean.

### Status text in test builds
When `VITE_LEVELPLAY_TEST=true`, a small black text box at the top left of the screen lists lines starting with "LP": whether the SDK started, and the error code and message whenever an ad or banner fails to load or show. It takes no taps. A store build (test line removed) never shows it. If no ad appears, read these lines first; they say whether LevelPlay did not start (key or network) or started but had no ad to give (dashboard setup or no fill).

### Not done yet (needed before a public release)
- Consent for players in the EEA, UK and similar regions. The plugin offers three consent providers: Usercentrics (needs an account and a settings id from usercentrics.com; check its pricing), InMobi Choice (needs a code from InMobi) and a built-in dialog that its own notes say is NOT valid for the EU. No provider is chosen or installed.
- Privacy policy, store data-safety answers about advertising, and a check of the merged manifest permissions.
- Mediation networks: only LevelPlay's own demand is included. Extra networks (more fill) are optional, are added through a `levelplay` block in `package.json`, and each needs its own account and checks; none is added.
- Real-device test. Nothing in this section has been run on a phone.

## Native size and flavors (open item)
The split above is in the web code. Both plugins are installed, so both native ad SDKs are still inside BOTH APKs (a JavaScript switch cannot remove native code), and the AdMob manifest app id is present in both. The store build therefore carries LevelPlay's native code unused, and the direct build carries AdMob's. Separating them properly needs Gradle product flavors; that has NOT been done or built here (no Android SDK). Test both APKs in Android Studio before any release, and check the APK size and the merged manifest.

## Behaviour (what the code does; device test still needed)
- Landscape only (`sensorLandscape`, both landscape directions), full screen with the system bars hidden (swipe from the edge shows them briefly).
- Home, app switcher or lock screen: the game saves, pauses (the Paused screen shows) and the sound stops. Coming back restarts sound but keeps the Paused screen until you tap Resume.
- Back button: closes Shop, Recipe Book or the restaurant list; otherwise pauses the game; on the title, Paused or Closed screen it sends the app to the background. It never quits the game and never reloads the page.
- No orientation or fullscreen web code runs in the app (the browser version still uses it).
